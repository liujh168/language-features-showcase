# 主题 03：模式匹配 Pattern Matching

> 同一道题：整数分类（0/1/负数/偶数/奇数）——六种语言有的游刃有余，有的退化为 if-else 链。
> 输出六个语言完全一致。交互展示页：[ui/index.html](ui/index.html)

## 题目

`classify(n)`：0 → "zero"，1 → "one"，负数 → "negative"，偶数 → "even"，否则 "odd"。对 0、1、-3、42、7 各调一次。

## 一句话看清六语言立场

| 语言 | 现状 | 关键差异 |
|---|---|---|
| **Rust** | `match` 是王牌特性 | 表达式可返回值；守卫（`n if ...`）；**编译器强制穷尽**——漏分支编译报错 |
| **Python** | `match-case`（3.10+） | 语法相似度最高的后来者；但漏了 `case _` 不报错（有运行时警告），也不强制穷尽 |
| **Go** | 没有模式匹配 | 无 tag `switch` 是惯用替代——本质是有语法糖的 if-else 链；默认不贯穿（无需 break） |
| **C++** | 至今没有 | C++23/26 仍无（P1371 提案拉锯多年）；现实就是 if-else 链，编译器不检查穷尽 |
| **TS** | 没有（提案阶段） | switch 处理离散值 + if 守卫补条件分支；TC39 pattern-matching 提案未落地 |

## 教学要点

1. **“模式匹配”与“条件分支”的差别**：前者对**值的形状**做解构（元组、枚举、结构体嵌套都能拆），后者只比较布尔条件。本例只用了整数守卫，Rust 版换成 `enum` + 解构才是 match 真正的威力（扩展练习）。
2. **穷尽性检查是安全网**：Rust 逼你列出所有情况；其他语言的 `default`/`else` 写不写全看你自觉。
3. **设计取舍**：Go/C++ 社区长期拒绝模式匹配，理由是“if-else 就够了，别加复杂度”——这个争论本身很有教学价值。
