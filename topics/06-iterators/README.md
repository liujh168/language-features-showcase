# 主题 06：迭代器与流 Iterators

> 同一道题：1..=10 中偶数 ×10，物化全量、取前 3、求和——
> 这道题专门暴露各语言“惰性”设计的差异。
> 输出六个语言完全一致。交互展示页：[ui/index.html](ui/index.html)

## 题目

对 1 到 10：筛偶数 → 乘 10 → 输出全量 `[20 40 60 80 100]`、前 3 个、总和（300）。

## 惰性光谱：六语言站在六个位置

| 语言 | 设施 | 惰性？ | 说明 |
|---|---|---|---|
| **Rust** | `Iterator` trait | ✅ 全惰性 | `filter/map` 搭管道不干活，`collect/sum/take` 才驱动；零成本抽象 |
| **C++20** | Ranges（`views::`） | ✅ 全惰性 | 管道语法 `| views::filter | views::transform`，思路与 Rust 同宗 |
| **Python** | 生成器 `yield` / 生成器表达式 | ✅ 可选 | `(x for x in ...)` 惰性、`[x for x in ...]` 立即；`itertools.islice` 惰性截取 |
| **TS** | 数组方法 / `function*` | ⚠️ 默认不惰性 | `filter/map` 每次都物化新数组；惰性要显式写 generator |
| **Go** | （经典无） | ❌ | 显式 for 循环组装切片。1.23+ 有 `iter` 包可写惰性管道，但非惯用 |
| **Java** | `Stream` | ✅ 管道惰性 | `filter/map` 不立即执行，`limit/collect/sum` 等终端操作才驱动 |

## 教学要点

1. **惰性 = 组合时不产生中间集合**：`(1..=10).filter(..).map(..).take(3)` 在 Rust/C++ 里只算 3 个元素就停；Python 生成器同理；TS 数组写法会把 5 个全算出来再截断。
2. **Go 的“缺失”是设计宣言**：Rob Pike 们认为显式循环更可读——惰性管道的链式写法在 Go 社区长期被视为“聪明过头”。
3. **`sum = 300` 不是笔误**：20+40+60+80+100 = 300，六个语言逐字节一致。

## 输出

```
evens doubled: 20 40 60 80 100
first 3: 20 40 60
sum = 300
```
